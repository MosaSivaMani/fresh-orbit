# Customer website gap audit (2026-10-29)

Scope: `apps/web`, every route, plus the shared packages it uses (`packages/ui`, `packages/core`,
`packages/api-client`), the `/api/v1` proxy and BFF, and the edge config in front of it (`infra/caddy/Caddyfile`).
Method: I read the code and checked each claim against the file and line cited. Nothing was built, run or installed
(CLAUDE.md rule 18), so nothing here was checked in a browser. Anything visual that could only be judged by eye
(for example the exact header wrap at 360 px) is left out.

## Summary

The website's flows are complete and follow rule 4: I found no money arithmetic in the browser (the only maths is
rupees → paise on the price filter, `lib/shop-params.ts:89`). The proxy, BFF, refresh rotation, If-Match handling and
per-action Idempotency-Key are mostly sound, and every list has loading, empty and error states. The gaps are in
four places:

1. **Legal and compliance.** The policy pages are still outlines. The footer has no legal entity, address,
   GSTIN, FSSAI number or grievance officer. Sign-in creates an account without the customer agreeing to the terms.
2. **Edge cases that hurt a real customer.**
   - Complaint photos are cut off at 1 MB by Caddy.
   - Place order can create a second order after an unclear 5xx.
   - Any refresh failure (429/503) signs the customer out.
   - The invoice opens in a popup that browsers block.
3. **Production operations.** There is no error monitoring and no analytics. The images are large and unoptimised
   (about 2.1 MB of hero pictures on the first screen, and product photos ignore the server's renditions).
4. **SEO details.** Crawlers see products without prices, so the JSON-LD has no `offers`. There is no default share
   image, no manifest, and no Organization, Breadcrumb or FAQ structured data.
