# Gap audit, October 2026: mobile account screens and app-wide

Scope: the Flutter app's Account tab (profile, addresses, settings, help, notifications, preferences, sign-out,
delete account) and everything app-wide (`lib/main.dart`, `lib/app.dart`, `lib/router.dart`, `lib/api/`,
`lib/core/`, `lib/demo/`, `android/`, `ios/`, `pubspec.yaml`, `.github/workflows/mobile-demo.yml`). Read-only
audit on 2026-10-29 at main `5e0907d`; nothing was built or run (CLAUDE.md rule 18). Every row was checked in the
code at the cited line.

## Summary

The account screens work: profile and address updates send `If-Match` and re-read after a 412, field errors sit at
the fields, delete account exists in the app (Settings › Delete my account → Profile) and on the website, tokens
sit in secure storage (refresh token only; access token in memory), nothing logs tokens or bodies, the demo code is
a compile-time constant that a store build refuses (`main.dart:16-19`), and no screen in scope calculates a
business value (rule 4). The release side is not ready: release builds are signed with the debug key, the launcher
icons are still the Flutter template icons (byte-identical to the SDK template), there is no in-app privacy policy
(the "Privacy and terms" row opens Help, which has none), and there is no crash reporting, no push and no store
build pipeline. Telugu and Hindi can be picked but no strings exist. Addresses have no map pin or location, so
every saved address has no latitude/longitude.

Earlier audits: `mobile-flow-audit-2026-10.md` F10–F14 (profile, inbox, help, navigation) are fixed and not
repeated. Its "Not verified" items are still open: the app has never been run as a release build on a phone (only
profile APKs, MA-14), and large text scale on account parts was never measured (MA-28, MA-53). The
`mobile-api-audit-2026-10.md` items are all closed. Still open from `team/next-steps.md` §7: `sync-mobile` writes
to `lib/core/illustrations/` while the widget lives in `lib/illustrations/` (MA-24).

Counts: **3 Blocker, 6 High, 15 Medium, 37 Low** (61 gaps), plus 22 missing features and details.

## Checked and fine

- `If-Match` on `PATCH /me` and `DELETE /me` (`account_state.dart:22-33`) and `PUT /me/addresses/{id}`
  (`account_state.dart:52-58`); 412 re-reads in profile (`account_screens.dart:319-322,358-361`) and address
  (`address_screens.dart:215-218`). `DELETE /me/addresses/{id}` takes no version on the server
  (`CustomersEndpoints.cs:67`). 428 cannot happen because every call sends the version.
- Tokens: refresh and guest-cart tokens in `flutter_secure_storage`, access token in memory (`token_store.dart`);
  no `print`, `debugPrint` or `LogInterceptor` anywhere in `lib/`.
- Sign-out works offline and clears the session; inbox, preferences, profile, addresses, wishlist, cart and orders
  follow the session.
- Delete account exists in the app and on the website (`apps/web/src/components/account/profile-view.tsx:108`), as
  Play requires.
- Demo code: `demoMode` is a compile-time constant, the demo panel is behind it, and a store release refuses it.
- `targetSdk`/`minSdk` follow the Flutter defaults (36 / 24 in this SDK), which meet Play's current target level.
- Android back in the shell (D234) and the header back fallback to Home (`router.dart:51-57`).
- No business value is computed in the account screens or the shell (the cart bar shows the server's estimated
  total).
