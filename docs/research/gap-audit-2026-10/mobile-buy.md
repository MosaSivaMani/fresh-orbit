# Gap audit: mobile buying and after-sale screens (October 2026)

Scope: the Flutter app's cart, checkout, order placed, orders list, order tracking, cancel, reorder,
substitutions, complaints with photos and invoice (`apps/mobile/lib/features/{cart,checkout,orders}`,
`state/cart_state.dart`, `state/checkout_state.dart`, `state/orders_state.dart`, `api/`), checked against the
backend endpoints in `backend/src/Modules/{Cart,Ordering,Promotions,Delivery,Payments}`.

## Summary

- Method: read-only code review on 2026-10-29 at `5e0907d`. Nothing was built or run (CLAUDE.md rule 18). Every
  row below cites the code it was checked against. Layout rows that depend on measuring are marked "not measured".
- The earlier audits' fixes still hold: `mobile-flow-audit-2026-10.md` F1–F14 and `mobile-api-audit-2026-10.md`
  M1–M5 and A1–A3. They are not repeated here. Their open items:
  - Cart lines carrying no order rules: **still open.** The server now sends them and the app ignores them (MO-9).
  - Large text not measured on the complaint sheet and the checkout edit button: **still open** (MO-16).
  - No end-to-end browse → checkout integration test: **still open** (MO-25).
- No client-side money maths was found. Totals, discounts, the delivery fee, the expected total and the
  substitution difference are all the server's, only formatted (rule 4 holds). Place order sends one
  Idempotency-Key per request body and blocks a double tap (`checkout_state.dart:222-266`).
- Biggest risks:
  1. **Checkout dead end** when the address is served by another store (MO-1).
  2. **A preview the app cannot read**: an empty cart or an unknown slot shows "We could not read the server
     response" (MO-2).
  3. **Leaving checkout while the order is being placed**: the success screen never shows, and the cart and
     orders stay stale (MO-3).
  4. **ONLINE payment**: the server would offer it the day a provider is configured, but the app has no way to
     pay (MO-5).
- Counts: Blocker 0, High 5, Medium 14, Low 40. Missing features and details are in a second table (MF-1…MF-30).
