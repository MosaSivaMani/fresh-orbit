# Gap audit: mobile entry flows (October 2026)

Scope: splash, onboarding, the pincode screen and "not served", sign-in (phone, code, first-run welcome),
"Tell us about you", the first-run router logic, the session, the auth interceptor and the token store
(`apps/mobile/lib/features/onboarding/`, `features/auth/`, `state/first_run.dart`, `state/session.dart`,
`router.dart`, `api/auth_interceptor.dart`, `api/token_store.dart`), and the backend endpoints they call
(`Identity` OTP / refresh / logout, `Locations` serviceability, `Customers` `PATCH /me`).

Method: I read the code only. Nothing was built or run (CLAUDE.md rule 18). I checked every row against the
file and line given. Earlier audits: `mobile-flow-audit-2026-10.md` (F1–F14) and `mobile-api-audit-2026-10.md`
(M1–M5, A1–A3). Their fixes in this area (D267 `leaveLogin`, the D271 429 wording, D236 change pincode) are
still in place, so they are not repeated here.

## Summary

The entry flows work on the happy path and look finished. The tests cover the layout at 360 × 640 and the
first-run routing. The real gaps are at the edges:

- **Privacy and terms.** The sign-in says "By continuing you agree to our terms and privacy policy", but neither
  document exists or is linked.
- **Token refresh after an error.** The app retries after a refresh only on `401 TOKEN_EXPIRED`. The server never
  sends that code: an expired token gets `UNAUTHENTICATED`. Only the refresh made before a request works, and that
  one depends on the phone's clock.
- **Errors on the code step.** A failed "Resend code" (429 too soon, or the SMS provider is down) writes its error
  to the phone field, which is hidden on the code step. The customer sees nothing.
- **Phone input.** Pasting or autofilling "+91 98765 43210" is cut to `9198765432`. That still passes the check,
  so the code goes to someone else's number.
- **Back on the code step.** On the first-run sign-in, Android Back on the code step closes the app instead of
  going back to the phone step.
- **No crash reporting and no global error handler.** A failure at launch, such as a keystore read in `main()`,
  stays invisible.

Then come the smaller gaps: copy, the theme, accessibility, missing tests and stale docs. Each has its own row,
as the owner asked.

Counts: **1 Blocker, 7 High, 15 Medium, 39 Low** (62 gaps), plus 20 missing features and details.
