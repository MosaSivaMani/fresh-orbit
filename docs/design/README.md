# Design system and shared front-end packages (Phase 5)

Owner: E3. Source of truth for tokens, components, front-end conventions and wireframe specifications for the
website (Next.js), admin dashboard (React + Vite) and mobile app (Flutter). Follows D24, D28, D29 and
`CLAUDE.md` rule 4: **the server computes, the front end renders.**

## 2. Technical choices (for the decision log)

| Topic | Choice | Why |
|---|---|---|
| Tailwind | **v4, CSS-first.** Tokens become CSS variables (`--fo-*`); a generated `@theme inline` block maps utilities to them. Tailwind's default colour palette is removed (`--color-*: initial`) so only token colours exist | One source for web and Flutter; dark mode is a variable swap, not `dark:` classes everywhere |
| Token build | Plain Node script with type stripping (`node scripts/build.ts`), no Style Dictionary | ~300 lines, zero dependencies, outputs exactly what we need |
| Dark mode | `[data-theme="dark"]` or `.dark` on any ancestor (usually `<html>`). Scoped: a subtree can be dark | Playground shows both side by side; apps toggle one attribute |
| TypeScript | 5.9.3 (not 7.0) | typescript-eslint 8.71 supports `<6.1`; openapi-typescript peers on `^5` |
| ESLint | 9.39.5 (not 10) | `eslint-plugin-jsx-a11y` 6.10.2 does not declare ESLint 10 support. ESLint 9 prints a deprecation notice on install; move to 10 when jsx-a11y does |
| TanStack Table | 8.21.3 (not 9.x) | v9 is a new API; v8 is stable and well known. Revisit in Phase 6 |
| Node | `engines.node >= 22.18` | First 22.x with TypeScript type stripping on by default (build scripts are `.ts`) |
| axe checks | `axe-core` directly (`packages/ui/test/axe.ts`), not `vitest-axe` | vitest-axe is unmaintained since 2022 |
| `@fresh/ui` bundle | Single ESM file with `"use client"`; React, `@fresh/core` external | Works in Next.js App Router and Vite |

## 4. Using the packages in an app

```css
/* app.css */
@import "tailwindcss";
@import "@fresh/config/tailwind.css";   /* tokens, theme, dark variant, base styles */
@import "@fresh/ui/styles.css";         /* lets Tailwind see @fresh/ui classes + animations */
```

```ts
// eslint.config.js            → export { default } from "@fresh/config/eslint/react";   (next: /eslint/next)
// tsconfig.json               → { "extends": "@fresh/config/tsconfig/vite-app.json" }  (next-app / react-library)
// prettier                    → root prettier.config.js already uses @fresh/config/prettier
const http = createHttpClient({ baseUrl: `${API}/api/v1`, getAccessToken, refresh: createRefreshHandler({ baseUrl: `${API}/api/v1`, tokenStore }), onAuthFailure });
const api = createApiClient({ baseUrl: API, fetch: http.fetch });   // typed paths from OpenAPI
const queryClient = createQueryClient();
```

Dark mode: set `document.documentElement.dataset.theme = "dark"` (or add class `dark`). Respect
`prefers-color-scheme` on first load; remember the user's choice.

## 6. Usage rules

1. **Render, never compute.** Prices, totals, discounts, savings %, delivery fees, net weights, stock and
   availability come from the API. `PriceTag` and `WeightLabel` only format; `QuantityStepper` only proposes a
   new quantity using the server's min/max/step and the UI then shows the server's response.
2. **Colours by role**, never raw hex or Tailwind palette names (the palette is removed). Status colour always
   comes with a text label.
3. **Customer surfaces (web, mobile) emphasise discovery:** generous spacing (`p-4`–`p-6`), large product
   imagery, `base`/`lg` text, one primary action per view (Add to cart, Checkout), warm sand only for offers and
   bestsellers, sticky cart summary on mobile.
4. **Admin emphasises density and clarity:** `compact` tables, `sm` text in tables, right-aligned tabular
   numbers (`meta: { align: "right" }`), filters in the URL, bulk actions only after selection, status badges
   consistent across screens.
5. **Calm motion.** Only fades/slides from `styles.css` at token durations; no gradients on surfaces. The one
   decorative animation is the gentle `float` on hero cut-outs (5 s, 8 px) and the polaroid tilt, both only under
   `motion-safe`; reduced motion respected.
6. **Errors.** Branch on `ApiError.code`. Field errors (`errors["items[1].quantity"]`) go to `FormField error`;
   other refusals to a toast or inline banner; failed loads to `ErrorState` with `traceId`. 412
   `CONCURRENCY_CONFLICT` → re-read and show "This changed since you opened it". 429 → respect `retryAfterSeconds`.
7. **Writes.** Retryable writes send one `Idempotency-Key` per user action (`createIdempotencyKey()`), reused on
   retry. Updates send `ifMatch: version` from the last read; the response `version` replaces it.
8. **Status maps** (`StatusMap`) live once per domain in each app (orders, shipments, payments, cities) — labels
   are UI copy, codes come from the API.

## 8. Accessibility rules

- WCAG 2.2 AA. Token contrast is unit-tested; components are tested with Testing Library by role and name, and
  with axe-core (`expectNoAxeViolations`) for FormField, RadioGroup, Switch, QuantityStepper, EmptyState,
  Pagination, Dialog, AppShell, DataTable and FilterBar.
- Every control has a visible label (or `aria-label` when the visual context is obvious, e.g. table filters).
- Focus is always visible (2 px `ring` outline, offset 2). Never remove outlines.
- Keyboard: everything reachable with Tab; menus/lists with arrows; Esc closes overlays; focus returns to the trigger.
- Touch targets ≥ 40 px on customer surfaces (Button `md`/`lg`, stepper `md`); admin may use 32 px (`sm`).
- Don't rely on colour: badges carry text, invalid fields carry an icon + message.
- Live regions: toasts, stepper value, pagination summary. Loading containers set `aria-busy`.
- Language `lang="en-IN"`; numbers via `en-IN` formatters; currency symbol ₹.
- ESLint `jsx-a11y` strict preset runs on all React code.

## 9. Flutter

`fresh_theme` is generated from the same JSON: `FreshColors` (a `ThemeExtension` with every semantic role, light
and dark, with `lerp` for animated theme switches), `FreshTypeScale`, `FreshSpacing`, `FreshRadius`,
`FreshDurations`, `FreshBreakpoints`, `FreshBrand`. `FreshTheme.light()/dark()` builds Material 3 `ThemeData`
(colour scheme: primary → primary, secondary → accent, tertiary → highlight, error → danger; text theme from
the type scale; filled/outlined/text buttons ≥ 48 px; outlined inputs with focus ring; flat bordered cards).
Read extra roles with `Theme.of(context).extension<FreshColors>()!`. Regenerate with `pnpm build`; commit
`tokens.g.dart`. `fresh_api` generation: see `packages/flutter/fresh_api/README.md`.

## 10. API client generation

`packages/api-client/openapi.json` is committed. At Phase 5 it was fetched from `FreshOrbit.Api` built from
`main` (Development, no database needed for `/openapi/v1.json`) and has **no paths yet**; regenerate after
Phase 3 merges:

```bash
dotnet run --project backend/src/Hosts/FreshOrbit.Api      # Development, listens on :5080
pnpm --filter @fresh/api-client fetch-spec                   # writes openapi.json (servers removed)
pnpm generate:api                                            # openapi-typescript → src/schema.d.ts
pnpm --filter @fresh/api-client check                        # fails if schema.d.ts is stale (for CI)
```

Paths in the document include `/api/v1`, so `createApiClient({ baseUrl: origin })`. Use
`unwrap(api.GET(...))` to get data or throw the same `ApiError` as `@fresh/core`.
