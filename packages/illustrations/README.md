# @fresh/illustrations

Every picture in the website, the admin dashboard and the mobile app fills one **slot** (D53). This package holds:

| Path                                   | What it is                                                                                                                                         |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `manifest.json`                        | The style block, the cast (Padma, Ravi, Anil, Ammamma, Chanduva) and one entry per slot: file, alt text, scene, prompt, aspect, background, status |
| `assets/<slot>.svg`                    | Our own clay-look placeholders, one per slot (generated by `pnpm --filter @fresh/illustrations placeholders`)                                      |
| `assets/<slot>.jpg` / `.png` / `.webp` | The final images, copied in by `import`                                                                                                            |
| `scripts/`                             | `import`, `validate`, `optimize`, `prompts`, `placeholders`, `build`, `sync-mobile`, `copy-assets.mjs`                                             |

`<slot>` is the slot code in lower snake case: `EMPTY_CART` → `empty_cart`. The full spec (cast, style rules, where
each slot appears) is in `docs/design/illustrations.md`.

## Making a final image (owner)

### 1. Generate it in ChatGPT or Gemini

Copy the slot's `prompt` from `manifest.json` (or from the prompt pack) into ChatGPT's image generation or Gemini.
Every prompt already contains the same style block and the same description of each character in it, so do not
rewrite prompts per image.

Before you rely on either service, **read its current terms for commercial use**; they change. Things to check:

| Service          | Check                                                                                                                                                                                                                   |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ChatGPT (OpenAI) | The terms in force when you generate; whether your plan allows commercial use of outputs; content rules for people. Output is PNG                                                                                       |
| Gemini (Google)  | The terms in force; images carry an invisible SynthID watermark, and some plans add a small **visible** mark in a corner. A visible mark breaks our "no logos, no watermark" rule: regenerate, or use a plan without it |

On every image, check by eye:

- **No text at all**: no letters, numbers or pseudo-letters on signs, boxes, screens, the scale dial or clothes.
  `validate` cannot see text, so this check is yours.
- The character matches the cast: same face, hair, clothes and colours as the reference image (below).
- Nothing resembles another brand's characters (including the friend's app the references came from) or a named
  studio's style.
- Hands and fins look right; fix small mistakes by asking for an edit of that area rather than starting over.

AI-generated images may have limited copyright protection in some countries; the brand's protection rests on the
name and logo, not on these pictures.

This laptop is a company machine: do not install image models or other tools on it. Everything below runs with the
project's own `pnpm` packages.

### 2. Keep the characters consistent

- Start each character with a **reference image**: a full-body front view on the sand background using that
  character's description. Keep the best one.
- For every later picture of that character, attach the reference image to the chat together with the slot's
  prompt and ask for "the same character as in the attached image".
- Generate a few versions and keep the one where the face, hair, clothes and colours match the reference.
- Keep the light, camera height and background the same across a set (onboarding, features, order states).
- If you change a character or the style, change `characters` or `stylePrompt` in `manifest.json` and run
  `pnpm --filter @fresh/illustrations prompts` so every prompt is rebuilt the same way.

### 3. Save it

| Setting | Value                                                                                                                        |
| ------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Folder  | `docs/design/characters/generated/`                                                                                          |
| Name    | `<slot>.jpg` when the picture has a full background, `<slot>.png` when it is transparent; for example `onboarding_fresh.jpg` |
| Size    | Longest side at least 1024 px, at most 600 KB (ChatGPT's 1536 x 1024 or a 1448 x 1086 export are fine)                       |
| Shape   | `1:1` slots square, `4:3` slots landscape (2% tolerance); `optimize` crops anything else                                     |

Full scene backgrounds (a harbour at sunrise, the market, a kitchen) are welcome: the components crop scenes with
`object-fit: cover` inside a rounded frame, so they fill feature cards, onboarding and the hero edge to edge.

### 4. Import it and validate

1. `pnpm --filter @fresh/illustrations run import` (`run` is needed: `pnpm import` is a pnpm command of its own).
   For every file in the folder it copies it to `assets/<slot>.<ext>` and, in `manifest.json`, sets `file`,
   `status: FINAL`, `width` and `height` (read from the file), the `source` it came from, and `background`
   (`TRANSPARENT` when the file has transparency, otherwise `SCENE`). Files already imported are skipped. It lists
   any image that still breaks a rule.
2. Check the slot's `alt` still describes the picture you made, and fix it in `manifest.json` if not.
3. Only if `import` listed a problem: `pnpm --filter @fresh/illustrations optimize`. It crops a JPEG or PNG to the
   slot's shape, scales the longest side to at most 1536 px, saves a WebP of at most 600 KB (transparency kept),
   points `file` at it and moves the original to `originals/` (not committed). It uses `sharp`, a normal npm
   package with a prebuilt binary. Images that already pass are left alone.
4. `pnpm --filter @fresh/illustrations validate`: every slot has a file, alt text and an up-to-date prompt; a FINAL
   file is named after its slot, is JPEG, PNG or WebP, at most 600 KB, at least 1024 px on its longest side, matches
   the slot's shape and the recorded width and height (read from the file header), and a `TRANSPARENT` slot's file
   really has transparency.
5. `pnpm build`: the website, admin and playground now show the final image (the SVG placeholder while the status is
   `PLACEHOLDER`).
6. For the mobile app: `pnpm --filter @fresh/illustrations sync-mobile` (copies the files into
   `apps/mobile/assets/illustrations/` and writes the Dart slot map, with `scene: true` for full pictures).
7. Commit the image and `manifest.json` together.

## Scripts

| Command                                           | What it does                                                                                                                                                     |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm --filter @fresh/illustrations run import`   | Copies finals from `docs/design/characters/generated/` (`-- --from <folder>` to change it) and marks the slots FINAL                                             |
| `pnpm --filter @fresh/illustrations validate`     | All the checks above; also no duplicate slots or files and placeholders under 6 KB                                                                               |
| `pnpm --filter @fresh/illustrations optimize`     | FINAL JPEG/PNG that is too heavy or the wrong shape → cropped, resized WebP ≤ 600 KB; original moved to `originals/`                                             |
| `pnpm --filter @fresh/illustrations prompts`      | Rebuilds every `prompt` from its `scene`, the cast and the style block                                                                                           |
| `pnpm --filter @fresh/illustrations placeholders` | Redraws every placeholder SVG from `src/placeholder-art.ts`                                                                                                      |
| `pnpm --filter @fresh/illustrations build`        | Validates, then writes `dist/index.js` (runtime fields only, no prompts) and the `IllustrationSlot` type                                                         |
| `pnpm --filter @fresh/illustrations sync-mobile`  | Copies the files to `apps/mobile/assets/illustrations/` and writes `apps/mobile/lib/core/illustrations/illustration_slots.g.dart` (`--dart <path>` to change it) |
| `fresh-illustrations-copy <folder>`               | For web apps: copies the files into a public folder, for example `public/illustrations`                                                                          |

## Using it in a web app

`@fresh/ui`'s `<Illustration slot="EMPTY_CART" />` reads this manifest and loads `<baseUrl>/<file>`; the base URL is
`/illustrations` unless an `IllustrationProvider` sets another. Copy the files into the app's public folder in its
`dev` and `build` scripts (pnpm does not run `pre` scripts by default):

```json
{
  "scripts": {
    "dev": "fresh-illustrations-copy public/illustrations && vite",
    "build": "fresh-illustrations-copy public/illustrations && vite build"
  }
}
```

Add `public/illustrations/` to the app's `.gitignore`. The playground (`apps/playground`) does exactly this.
