# @fresh/illustrations

Every picture in the website, the admin dashboard and the mobile app fills one **slot** (D53). This package holds:

| Path | What it is |
|---|---|
| `manifest.json` | The style block, the character sheet and one entry per slot: file, alt text, scene, prompt, aspect, background, status |
| `assets/*.svg` | Our own flat placeholders (one per slot, generated by `pnpm --filter @fresh/illustrations placeholders`) |
| `assets/*.webp` | The final images, once you generate them |
| `scripts/` | `validate`, `prompts`, `placeholders`, `build`, `sync-mobile`, `copy-assets.mjs` |

The full spec (cast, style rules, where each slot appears) is in `docs/design/illustrations.md`.

## How to make a final image (owner)

### 1. Pick a generator whose licence allows commercial use

All three are free. **Read the current terms yourself before you use one**: licences and service terms change.

| Option | Licence | Caveats |
|---|---|---|
| **FLUX.1 [schnell]**, run on your own computer (for example with ComfyUI or the `diffusers` library) | Apache-2.0 (model weights); you own what you generate | Recommended. Needs a recent GPU (about 12 GB of video memory) or an Apple Silicon Mac with 16 GB or more using a quantised build; slower on a Mac. Do **not** use FLUX.1 **[dev]**: its licence is non-commercial. |
| **Stable Diffusion XL 1.0** (base), run on your own computer (ComfyUI, Fooocus) | CreativeML Open RAIL++-M: commercial use allowed, with use restrictions (no harmful uses) | Softer at faces than FLUX; adds a refiner step. The restrictions travel with the model, not with your images. |
| **A free hosted demo of FLUX.1 [schnell]** (for example a Hugging Face Space running the official weights) | The model is Apache-2.0, but **the host's own terms also apply** | Daily free quota; your prompts run on someone else's server; some hosts keep or publish what you generate. Check the host's terms for commercial use before you rely on it. |

Whatever you use: the images must not copy or resemble any existing brand's characters (including the reference screenshots
from the friend's app), must not imitate a named artist or studio, and must contain **no text, letters, logos or watermarks**. Reject
any picture with pseudo-letters on signs, boxes or screens. AI-generated images may have limited copyright protection in
some countries, so the brand's protection rests on the name and logo, not on these pictures.

### 2. Keep the characters consistent

- Use the slot's `prompt` from `manifest.json` **exactly**. Every prompt already contains the same style block and the same
  character description, so do not rewrite them per image. If you want to change a character or the style, edit
  `characters` or `stylePrompt` in the manifest, then run `pnpm --filter @fresh/illustrations prompts` so every prompt is
  rebuilt the same way.
- Make a **reference image of each character first** (a simple full-body front view on the sand background). Keep the seed
  you liked. Use that reference for every later picture of the character (image-to-image at low strength, or an image
  reference/adapter node in ComfyUI).
- Generate 4 to 8 versions of each slot and keep the one where the face, hair, clothes and colours match the reference.
  Fix small differences (wrong clothes colour, extra fingers) by inpainting, not by re-prompting from scratch.
- If you make many images, train a small LoRA on 15–20 approved pictures of each character; it keeps faces steady.
- Keep the light, the camera height and the background the same across a set (onboarding, features, order states).

### 3. Export

| Setting | Value |
|---|---|
| Format | WebP (quality 80–85), sRGB, metadata removed |
| Size | Longest side 1024–1536 px; `1:1` slots square, `4:3` slots landscape (for example 1280 x 960) |
| Weight | 150 KB or less per file |
| Background | `SAND` slots keep the sand backdrop. `TRANSPARENT` slots: remove the background (for example with the free `rembg` tool, MIT) and save the WebP with transparency |

Free export tools: `cwebp -q 82 -resize 1280 0 in.png -o out.webp` (libwebp, BSD licence) or Squoosh in the browser
(Apache-2.0).

### 4. Swap it in and validate

1. Save the file as `packages/illustrations/assets/<slot-name>.webp`, using the same name as the placeholder
   (for example `assets/empty-cart.webp` next to `assets/empty-cart.svg`). Keep the SVG.
2. In `manifest.json`, for that slot: set `"file": "assets/empty-cart.webp"` and `"status": "FINAL"`. Do not change
   `placeholder`.
3. Run `pnpm --filter @fresh/illustrations validate`. It checks that the file exists, is a WebP of at most 150 KB, has a
   longest side of at least 1024 px and matches the slot's aspect. Fix anything it lists.
4. Run `pnpm build`. The website, admin and playground now show the WebP (they fall back to the SVG while the status is
   `PLACEHOLDER`).
5. For the mobile app: `pnpm --filter @fresh/illustrations sync-mobile` (copies the files into
   `apps/mobile/assets/illustrations/` and writes the Dart slot map).
6. Commit the WebP and the manifest together.

## Scripts

| Command | What it does |
|---|---|
| `pnpm --filter @fresh/illustrations validate` | Every slot has a file, alt text and an up-to-date prompt; no duplicate slots or files; placeholders under 6 KB; FINAL files are WebP, ≤ 150 KB, longest side ≥ 1024 px (read from the file header), right aspect |
| `pnpm --filter @fresh/illustrations prompts` | Rebuilds every `prompt` from its `scene`, the character sheet and the style block |
| `pnpm --filter @fresh/illustrations placeholders` | Redraws every placeholder SVG from `src/placeholder-art.ts` |
| `pnpm --filter @fresh/illustrations build` | Validates, then writes `dist/index.js` (runtime fields only, no prompts) and the `IllustrationSlot` type |
| `pnpm --filter @fresh/illustrations sync-mobile` | Copies the files to `apps/mobile/assets/illustrations/` and writes `apps/mobile/lib/core/illustrations/illustration_slots.g.dart` (`--dart <path>` to change it) |
| `fresh-illustrations-copy <folder>` | For web apps: copies the files into a public folder, for example `public/illustrations` |

## Using it in a web app

`@fresh/ui`'s `<Illustration slot="EMPTY_CART" />` reads this manifest and loads `<baseUrl>/<file>`; the base URL is
`/illustrations` unless an `IllustrationProvider` sets another. Copy the files into the app's public folder before
`dev` and `build`:

```json
{ "scripts": { "predev": "fresh-illustrations-copy public/illustrations", "prebuild": "fresh-illustrations-copy public/illustrations" } }
```

Add `public/illustrations/` to the app's `.gitignore`.
